# Thai Law RAG API — คู่มือสำหรับผู้เรียกใช้

ระบบถาม-ตอบประมวลกฎหมายที่ดิน พ.ศ. ๒๔๙๗ · ทุก endpoint อยู่ใต้ `/v1`

ตอบพร้อมอ้างอิงเลขมาตราและหน้าเสมอ และตอบจากเอกสารเท่านั้น — ไม่แต่งคำตอบขึ้นเอง

---

## เริ่มใช้

```bash
curl -N http://<host>:8000/v1/chat \
  -H "X-API-Key: <คีย์ที่ได้รับ>" \
  -H "Content-Type: application/json" \
  -d '{"question":"ที่ดินที่ออกใบจองห้ามโอนภายในกี่ปี"}'
```

- ทุก endpoint ยกเว้น `/health` ต้องส่ง header **`X-API-Key`** · คีย์ผิดหรือไม่ส่ง → `401`
- เรียกจากเบราว์เซอร์ต้องแจ้งโดเมนมาก่อน เพื่อเปิด CORS ให้ (ค่าเริ่มต้นปิดทุกโดเมน)
  · เรียกจาก server / CLI / curl ไม่ต้องทำอะไร

---

## Endpoints

| Method | Path | ทำอะไร |
|---|---|---|
| `GET` | `/health` | เช็คสถานะระบบ — **ไม่ต้องใช้คีย์** |
| `GET` | `/v1/groups` | รายชื่อกลุ่มเอกสาร |
| `GET` | `/v1/years` | ปีเอกสารที่มีในระบบ |
| `GET` | `/v1/models` | รุ่น LLM ที่เลือกได้ |
| `POST` | `/v1/chat` | **ถามคำถาม** — ตอบแบบสตรีม (SSE) |
| `POST` | `/v1/feedback` | ส่ง 👍 / 👎 กลับมา |

### รูปแบบผลลัพธ์ของ 3 endpoint แรก

```jsonc
// GET /v1/groups
{"groups": ["ฉบับดั้งเดิม พ.ศ. ๒๔๙๗", "ฉบับย้อนหลังตามช่วงเวลา",
            "ฉบับใช้บังคับปัจจุบัน", "ประวัติการแก้ไข"]}

// GET /v1/years — ปีที่มีเอกสารจริง (13 ปี)
{"years": [2520, 2521, 2526, 2528, ...]}

// GET /v1/models — มาจาก endpoint ที่ระบบต่ออยู่ อาจเปลี่ยนได้
{"models": ["google/gemma-4-26b-a4b-it", "qwen/qwen3-8b", ...]}
```

> ปกติ**ไม่ต้องเรียก 3 ตัวนี้เลย** — ระบบเลือกกลุ่มและปีเองอัตโนมัติ
> มีไว้เผื่อกรณีที่อยากทำ UI ให้ผู้ใช้เลือกเอง

## `POST /v1/chat`

### Request

```json
{
  "question": "ที่ดินที่ออกใบจองห้ามโอนภายในกี่ปี",
  "history": [],
  "auto_group": true,
  "groups": null,
  "years": null,
  "model": null
}
```

| ฟิลด์ | ชนิด | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|---|
| `question` | string | **จำเป็น** | 1–2000 ตัวอักษร |
| `history` | array | `[]` | คำถามต่อเนื่อง — `[{"role":"user"\|"assistant","content":"..."}]` สูงสุด 20 รายการ · ⚠️ ดูข้อ 1 |
| `auto_group` | bool | `true` | ให้ระบบเลือกกลุ่มเอกสารเอง — **แนะนำให้ปล่อยไว้** |
| `groups` | array\|null | `null` | ระบุกลุ่มเอง (ใช้เมื่อ `auto_group=false`) ค่าต้องมาจาก `/v1/groups` |
| `years` | array\|null | `null` | กรองปีเอกสาร ค่าต้องมาจาก `/v1/years` |
| `model` | string\|null | `null` | ต้องอยู่ใน `/v1/models` ไม่งั้น `400` |

**ส่งแค่ `question` ก็พอสำหรับการใช้งานทั่วไป** — ฟิลด์ที่เหลือมีไว้ให้ควบคุมเมื่อจำเป็น

### Response — Server-Sent Events

`Content-Type: text/event-stream` · แต่ละบรรทัดคือ `data: {json}\n\n`

```
data: {"stage": "เลือกกลุ่มเอกสาร"}
data: {"stage": "แตกคำถามเป็นหลายมุมค้นหา"}
data: {"meta": {"groups": ["ฉบับใช้บังคับปัจจุบัน"], "n_sources": 12,
                "retrieval_mode": "hybrid", "search_q": ""}}
data: {"stage": "เขียนคำตอบ"}
data: {"token": "ตามมาตรา ๓๑ "}
data: {"token": "ที่ดินที่ออกใบจอง..."}
data: {"final": {"answer": "...", "chunks": [...], "groups_used": [...],
                 "retrieval_mode": "hybrid", "search_q": "", "elapsed": 18.4}}
```

### ชนิดของ event ทั้งหมด

| event | ชนิด | ใช้ทำอะไร |
|---|---|---|
| `stage` | string | ข้อความความคืบหน้าภาษาไทย เอาไว้โชว์ระหว่างรอ · **ควรแสดงเสมอ** เพราะรอนาน |
| `meta` | object | ข้อมูลประกอบ มาก่อนคำตอบเริ่มไหล |
| `token` | string | ชิ้นส่วนคำตอบ — ต่อกันเองฝั่ง client |
| `reasoning` | string | เฉพาะบางรุ่นที่ส่งความคิดออกมาก่อนตอบ · **ไม่ใช่คำตอบ อย่าเอาไปแสดงปนกับ `token`** |
| `final` | object | คำตอบเต็ม + แหล่งอ้างอิง — เป็น event สุดท้ายเสมอเมื่อสำเร็จ |
| `error` | object | เกิดปัญหากลางคัน สตรีมจบเท่านี้ |

> **ถ้าไม่อยากทำ streaming UI** — ข้าม `token` ทั้งหมด รอ `final.answer` อย่างเดียวก็ได้
> คำตอบเต็มอยู่ในนั้นแล้ว

### ฟิลด์ใน `meta`

| ฟิลด์ | ความหมาย |
|---|---|
| `groups` | กลุ่มเอกสารที่ระบบเลือกค้นจริง |
| `n_sources` | จำนวนตัวบทที่จะใช้ตอบ (ปกติ 12) |
| `retrieval_mode` | `hybrid` หรือ `bm25_only` — **ดูหัวข้อถัดไป** |
| `search_q` | คำถามหลังถูกเขียนใหม่ · **ว่าง = ไม่ได้แก้** · มีค่าเมื่อส่ง `history` มาเท่านั้น |

`search_q` มีประโยชน์มากเวลา debug คำถามต่อเนื่อง — ถ้าคำตอบหลุดประเด็น
ให้ดูค่านี้ก่อนว่าระบบตีความคำถามว่าอะไร

### ฟิลด์ใน `final`

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `answer` | string | คำตอบเต็มในรูปแบบ Markdown |
| `chunks` | array | ตัวบทที่ใช้ตอบ (ปกติ 12 ก้อน) — ดูโครงสร้างด้านล่าง |
| `groups_used` | array | กลุ่มเอกสารที่ใช้จริง |
| `retrieval_mode` | string | `hybrid` / `bm25_only` |
| `search_q` | string | เหมือนใน `meta` |
| `elapsed` | number | เวลาที่ใช้ทั้งหมด (วินาที) |

### โครงสร้างของ `chunks[i]`

แต่ละก้อนมี 20 กว่าฟิลด์ · **ที่ใช้ทำ UI แหล่งอ้างอิงจริง ๆ มี 6 ตัว**

| ฟิลด์ | ตัวอย่าง | ใช้ทำอะไร |
|---|---|---|
| `article` | `"มาตรา ๑๐๘"` | หัวข้อของแหล่งอ้างอิง |
| `page_start` / `page_end` | `35` / `36` | เลขหน้า — ก้อนเดียวคร่อมหน้าได้ |
| `doc_label` | `"ประมวลกฎหมายที่ดิน (ฉบับใช้บังคับปัจจุบัน)"` | ชื่อเอกสารแบบอ่านออก |
| `in_force` | `true` | ⚠️ **`false` = ตัวบทนี้ไม่ใช่ฉบับที่ใช้บังคับแล้ว** ควรติดป้ายเตือนใน UI |
| `text` | `"ห้าพันบาท หรือ..."` | เนื้อความจริง |
| `id` | `"LandCode2497_Update-vlast_TruePDF.pdf::0062"` | ย้อนกลับไปหาไฟล์ต้นทางได้ |

ฟิลด์ที่เหลือ (`group`, `kind`, `version`, `as_of_year`, `amend_no`, `articles`,
`article_nums`, `refs`, `section`, `is_scan`, ...) เป็นข้อมูลภายในที่ใช้กรอง/จัดอันดับ
ปล่อยผ่านได้

> ⚠️ **`final.chunks` หนักประมาณ 22 KB ต่อคำตอบ** — ถ้าไม่ได้ใช้ทำ UI แหล่งอ้างอิง
> อย่าเก็บลงฐานข้อมูลทั้งก้อน เก็บแค่ `id` กับ `article` พอ

### รูปแบบของ `error`

```json
{"error": {"code": "stream_failed",
           "detail": "ระบบตอบไม่สำเร็จกลางคัน ลองใหม่อีกครั้ง"}}
```

`detail` เป็นข้อความภาษาไทยที่แสดงให้ผู้ใช้เห็นได้เลย
· รายละเอียดทางเทคนิคอยู่ใน log ฝั่งเซิร์ฟเวอร์ ไม่ส่งออกมา

## `POST /v1/feedback`

```json
{
  "rating": "up",
  "question": "ที่ดินที่ออกใบจองห้ามโอนภายในกี่ปี",
  "answer": "ตามมาตรา ๓๑ ...",
  "model": "google/gemma-4-26b-a4b-it"
}
```

| ฟิลด์ | ชนิด | จำเป็น | หมายเหตุ |
|---|---|---|---|
| `rating` | `"up"` \| `"down"` | ✅ | ค่าอื่นได้ `422` |
| `question` | string | — | สูงสุด 2000 ตัวอักษร |
| `answer` | string | — | สูงสุด 20000 ตัวอักษร |
| `model` | string | — | รุ่นที่ใช้ตอบ |

ตอบกลับ `{"ok": true}` · **ส่ง `question` กับ `answer` มาด้วยเสมอ**
ไม่งั้นเราไล่ไม่ถูกว่าคำตอบไหนมีปัญหา — โดยเฉพาะเวลากด 👎

---

## ⚠️ `retrieval_mode` — ต้องดูทุกครั้ง

| ค่า | แปลว่า |
|---|---|
| `hybrid` | ปกติ — ค้นด้วยความหมาย + คำสำคัญ |
| `bm25_only` | **ระบบค้นด้วยความหมายใช้ไม่ได้ชั่วคราว** ค้นด้วยคำสำคัญอย่างเดียว |

โหมด `bm25_only` ยังตอบได้ แต่**แม่นน้อยลง** โดยเฉพาะเมื่อผู้ใช้ใช้คำต่างจากตัวบท
(ถาม *"บุกรุก"* แต่กฎหมายเขียน *"เข้าไปยึดถือครอบครอง"*)

`final.answer` จะมีป้ายกำกับมาให้แล้ว แต่**ควรแสดงเตือนใน UI ด้วย**

## ข้อควรรู้ก่อนใช้งานจริง

### 1. `history` วัดผลแล้ว แต่ยังไม่นิ่ง 100%

มีชุดวัดคำถามต่อเนื่องแยกต่างหาก (6 บทสนทนา 13 เทิร์น) คำตอบถูก **13/13**
แต่จุดที่ยังแกว่งคือตอน**ผู้ใช้เปลี่ยนเรื่องกลางบทสนทนา** — ระบบอาจลากหัวข้อเดิม
มาปนคำถามใหม่ ทำให้ตอบไม่ครบ (ประมาณ 1 ใน 2 รอบ)

**ถ้าจะถามเรื่องใหม่ที่ไม่เกี่ยวกับก่อนหน้า แนะนำให้ส่ง `history: []`** จะแม่นกว่า

### 2. ยิงพร้อมกันได้ไม่เกิน ~3 คำขอ

รับพร้อมกันได้จริง (ไม่ได้เข้าคิวทีละคน) แต่ยิ่งพร้อมกันมาก แต่ละคนยิ่งรอนาน

| ยิงพร้อมกัน | แต่ละคนรอ | เทียบกับคนเดียว |
|---|---|---|
| 1 | 22.6s | — |
| 3 | 32.8s | ช้าลง 1.5 เท่า |
| 5 | 47.5s | ช้าลง 2.1 เท่า |
| 8 | 138.2s | **ช้าลง 6.1 เท่า** ← พังตรงนี้ |

**ไม่มีการจำกัดจำนวนคำขอฝั่งเซิร์ฟเวอร์ — กรุณาจำกัดที่ 3 คำขอพร้อมกันฝั่งผู้เรียกเอง**

· คำตอบยังถูกต้องทุกระดับ (ทดสอบแล้วไม่มีคำตอบข้ามคำถามกัน) แค่ช้าลง
· ยิงต่อเนื่อง 20 ครั้งติด: ช้าลง 13% ไม่มีคำขอไหนพัง

### 3. คำถามหนึ่งใช้ 8–140 วินาที — แกว่งมาก

เวลาไม่ได้ขึ้นกับความยากของคำถามอย่างเดียว แต่ขึ้นกับ**ภาระของ LLM endpoint ตอนนั้น**ด้วย
วัดคำถามเดียวกัน 3 รอบติดได้ **30s / 59s / 139s**

**ตั้ง timeout ฝั่ง client ที่ 300 วินาที** และแสดง `stage` เสมอ —
ถ้าเงียบเกิน 20 วินาทีผู้ใช้จะคิดว่าค้าง

> ฝั่งเซิร์ฟเวอร์ตั้ง timeout 120 วินาทีต่อการเรียก LLM หนึ่งครั้ง (ไม่ใช่ต่อคำถาม)
> ถ้าชนเพดานจริง ระบบจะ**คืนตัวบทที่ค้นเจอแทน** ไม่ใช่คืน error เปล่า
> — คำตอบจะขึ้นต้นด้วยคำเตือนว่ายังไม่ได้เรียบเรียง

### 4. บูตช้า แต่พร้อมแล้วพร้อมจริง

เซิร์ฟเวอร์ใช้เวลา ~1-2 นาทีก่อน `/health` ตอบ เพราะอุ่นทุกอย่างให้เสร็จก่อน
(ดัชนี · ตัวตัดคำ · โมเดลจัดอันดับ) — **`/health` ตอบเมื่อไร = ยิงได้เต็มความเร็วเมื่อนั้น**

เช็ค `/health` ก่อนเริ่มยิงจริงเสมอ อย่าเดาเวลาเอา

### 5. `/health` บอกสถานะคุณภาพด้วย

```json
{"status": "ok", "version": "v1", "chunks": 2068,
 "model": "google/gemma-4-26b-a4b-it", "tokenizer": "newmm", "rerank": true}
```

| ฟิลด์ | ค่าที่ควรเป็น | ถ้าไม่ใช่ |
|---|---|---|
| `status` | `ok` | `degraded` = ระบบยังตอบได้แต่คุณภาพลด |
| `tokenizer` | `newmm` | `bigram` = ค้นด้วยคำหยาบลงมาก |
| `rerank` | `true` | `false` = ข้ามขั้นจัดอันดับ เร็วขึ้นแต่แม่นลง |
| `chunks` | `2068` | น้อยกว่านี้มาก = เอกสารโหลดไม่ครบ |

**ควรมอนิเตอร์ `status` ไม่ใช่แค่ HTTP 200** — ระบบเสื่อมยังตอบ 200 อยู่

### 6. ตอบจากเอกสารเท่านั้น

ถ้าคำตอบไม่มีในเอกสาร ระบบจะบอกว่าไม่พบ — **ไม่แต่งขึ้นมาเอง**
(วัดด้วยคำถามหลอก 12 ข้อ ผ่านทั้งหมด)

**สิ่งที่ระบบตอบไม่ได้ และจะบอกตรง ๆ ว่าตอบไม่ได้**

- เนื้อหาของประกาศคณะปฏิวัติ ฉบับที่ ๓๓๔ และ ๙๖ — ไม่มีตัวบทในคลัง
  ระบบตอบได้ว่า "มาตรานี้มีต้นสายมาจากฉบับนั้น" แต่ตอบไม่ได้ว่าเนื้อหาเดิมเขียนว่าอะไร
- กฎหมายอื่นนอกเหนือจากประมวลกฎหมายที่ดิน
- การให้ความเห็นทางกฎหมายหรือการปรับใช้กับกรณีเฉพาะราย

## รหัสข้อผิดพลาด

| รหัส | ความหมาย | แก้ยังไง |
|---|---|---|
| `401` | คีย์ผิดหรือไม่ได้ส่ง | เช็ค header `X-API-Key` |
| `400` | `model` ที่ระบุไม่มีในระบบ | เอาค่าจาก `/v1/models` |
| `422` | ข้อมูลไม่ถูกรูปแบบ | คำถามว่าง · `role` ไม่ใช่ user/assistant · `rating` ไม่ใช่ up/down |
| `500` | ข้อผิดพลาดภายใน | ลองใหม่ · ถ้าซ้ำให้แจ้งเรา รายละเอียดอยู่ใน log ฝั่งเซิร์ฟเวอร์ |

> ⚠️ **`/v1/chat` ที่เริ่มสตรีมไปแล้วจะไม่เปลี่ยน HTTP status** — ปัญหาที่เกิดกลางคัน
> จะมาเป็น `error` event แทน (HTTP ยังเป็น 200) · **ต้องดัก `error` event ด้วย ไม่ใช่ดูแค่ status code**

## เรื่องเวอร์ชัน

ทุก endpoint อยู่ใต้ `/v1` เพราะเมื่อมีคนใช้แล้ว รูปแบบข้อมูลจะกลายเป็นสัญญา

## ตัวอย่าง Python

```python
import json, httpx

BASE = "http://<host>:8000"
KEY  = "<คีย์>"

def ask(question: str, history: list | None = None) -> dict:
    """ถาม 1 คำถาม -> คืน dict ของ final (หรือโยน RuntimeError ถ้าพัง)"""
    answer, final, err = "", None, None
    with httpx.stream(
        "POST", f"{BASE}/v1/chat",
        headers={"X-API-Key": KEY},
        json={"question": question, "history": history or []},
        timeout=300,                      # เวลาตอบแกว่ง 8-140 วินาที ตั้งเผื่อไว้
    ) as r:
        r.raise_for_status()
        for line in r.iter_lines():
            if not line.startswith("data: "):
                continue
            ev = json.loads(line[6:])

            if "stage" in ev:             # โชว์ให้ผู้ใช้เห็นว่ายังทำงานอยู่
                print(f"  ... {ev['stage']}")
            elif "token" in ev:           # ต่อกันเองเป็นคำตอบ
                answer += ev["token"]
            elif "final" in ev:
                final = ev["final"]
            elif "error" in ev:           # HTTP ยัง 200 ต้องดักตรงนี้เอง
                err = ev["error"]["detail"]

    if err:
        raise RuntimeError(err)
    if final is None:
        raise RuntimeError("สตรีมจบโดยไม่มี final")
    return final


final = ask("ใครมีอำนาจเพิกถอนโฉนดที่ดิน")

print(final["answer"])

if final["retrieval_mode"] == "bm25_only":
    print("⚠️ ค้นได้ไม่เต็มความสามารถ ควรตรวจซ้ำ")

print(f"\nอ้างอิง {len(final['chunks'])} ตัวบท ({final['elapsed']:.0f} วินาที):")
for c in final["chunks"][:5]:
    flag = "" if c["in_force"] else "  ⚠️ ไม่ใช่ฉบับที่ใช้บังคับ"
    print(f"  {c['article']} · หน้า {c['page_start']} · {c['doc_label']}{flag}")
```

### คำถามต่อเนื่อง

```python
history = []
for q in ["โฉนดที่ดินชำรุดหรือสูญหาย เจ้าของต้องขอเอกสารใด",
          "แล้วฉบับเดิมล่ะ"]:
    final = ask(q, history)
    print(final["answer"])
    history += [{"role": "user", "content": q},
                {"role": "assistant", "content": final["answer"]}]
```

⚠️ **เปลี่ยนเรื่องเมื่อไร ให้ล้าง `history` ก่อน** (ดูข้อ 1)
